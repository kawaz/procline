# env を照合の項目に足す (弱い条件として)

## 概要

組み込みの照合の項目に env が無い (`process`、`binary`、`uid`、`gid`、`path`、`cwd`、`argv`、`name`、`tty`、`responsible`)。「`MYTEST=1` が付いたプロセスは通す」のような、利用者の都合での範囲の指定に使えるよう、env を項目に足す。

方針 (kawaz 2026-11-17): 弱い条件は、事故の防止や気軽な範囲の指定のためにあってよい。同じ uid のプロセスが値を決められることは、項目を置かない理由にならない。安全の度合いは強さのクラスの表示で伝え、弱い条件を拒むかどうかはアプリが決める (パスワードの強さの表示と同じで、弱くても設定はできる)。

## 背景 (事実)

- 収集は env を `ProcessInfo.env` (`Option<BTreeMap<String, String>>`) に入れる。既定では集めず (`EnvPolicy::None`)、`Allowlist` か `All` で集める
- 集めた値は伏せ字を通した後のもの。既定では、名前に `TOKEN`、`KEY`、`PASS` などを含む変数の値が `[redacted]` に置き換わる
- 照合は収集済みの列だけを見て、OS を呼ばない

## 決めること

- 書き方は 2 通り (kawaz 2026-11-17):
  - 直値: 変数の名前と値を rule に書く (`{"MYTEST": "1"}`)
  - pin: `process` と同じく、承認した時に集めた値で埋める (`{"MYTEST": true}`。placeholder の仕組みに乗る)
- 残る細部: 値の glob を書けるか、名前だけ (ある・ない) の条件を持つか、pin で変数が集まっていなかった時 (placeholder を埋められない時のエラーにするか)
- 集めていない変数を条件にした時: 列に env が無い、またはその変数を集めていない時の結果 (当たらない、とするか、判定できない、とするか)
- 伏せ字になった値を条件にした時の扱い (伏せた後の値とは比べられない)
- クラスは弱
