# DR-0017: `sanitize_for_display` のエスケープの書き方、対象の文字、長さの数え方、切り詰めの印を定める

- Status: Proposed
- Date: 2026-11-15

## Context

argv、パス、env の値は、同じ uid の別プロセスが自由に決められる文字列で、承認画面やログにそのまま出る。画面に出した文字列が、表示の向きを入れ替えたり、端末を操作したり、前後の表示を押し流したりすると、利用者は実際とは別のコマンドを見て判断することになる。

決まっていること (DESIGN-ja「表示用の無害化」、[DR-0001](DR-0001-crate-naming.md) の core の責務、`crates/procline-core/src/sanitize.rs` の doc):

- 制御文字と bidi の制御文字はエスケープして見せる
- 長すぎる値は、切り詰めたことが分かる形で切り詰める
- 照合には元の値を使う
- 形は `fn sanitize_for_display(value: &str, max_chars: usize) -> String`、置き場は procline-core

決まっていないことは [findings](../findings/2026-11-15-load-entry-recon.md) の 7 にある (エスケープの書き方、対象の文字の範囲、元の文字列との区別、`max_chars` の単位、切り詰めの印)。関数は `todo!()` で、呼び出す箇所はまだ無い。

- 目的: 相手が決めた文字列を画面に出した時に、その文字列が自分の外の表示を変えず (向きの入れ替え、端末の操作、行の送り)、出る量に上限があり、切り詰められたことが利用者に分かる
- 増やしたくないもの:
  - 関数の入口と引数 (表示先ごとの変種、挙動を切り替えるオプション)
  - procline-core の依存 (今は `serde`、`serde_json`、`base64` だけ。Unicode の表を持つ crate を足さない)
  - 表示先の知識 (端末の桁幅、フォント、HTML の構文) を core が持つこと
  - 場合分け (`max_chars` の特定の値だけの扱い、文字ごとに違う書き方)

扱わないもの (誰の責務か):

| 扱わないもの | 責務 |
|---|---|
| 表示先の構文のエスケープ (HTML の `<` や `&`、シェルの引用) | 表示するアプリ。この関数の出力を、表示先の決まりでさらにエスケープする |
| 見た目が似た別の文字 (キリル文字の а とラテン文字の a など) | 表示するアプリ。名前やパスは誰でも真似できるので、信頼の印と Team ID を並べて出す (DESIGN-ja「署名の検証と信頼の印」) |
| 値の区切りを見せること (引数の境目、前後の空白、空白に見える別の文字) | 表示するアプリ。関数は値を 1 つずつ受け取り、値の外を知らない。値ごとに枠や引用符で囲むのは表示の側 |
| 結合文字を重ねて隣の行にはみ出す表示 | 表示するアプリ (行の高さや切り抜きは表示先の機能) |
| UTF-8 でないバイト列 (パス) をどう文字列にするか | 呼び出し側。関数は `&str` を受け取る |
| 表示の桁幅に合わせた切り詰め | 表示するアプリ。桁幅は端末とフォントで決まる |

## Decision

### どの選択肢でも変わらない部分

走査と出力:

- 値を先頭から char (Unicode のスカラ値) ごとに見て、対象の文字はエスケープに置き換え、それ以外はそのまま出す。順序は変えない
- エスケープは、どの code point も書ける `\u{<16 進>}` を持つ。16 進は小文字で、先頭に 0 を足さない (U+202E は `\u{202e}`、改行は `\u{a}`)。標準ライブラリの `char::escape_unicode` と同じ形
- 関数は 1 つで、引数は今のまま (`value`、`max_chars`)。出力を元に戻す関数は持たない

対象に必ず入る文字 (DESIGN-ja「表示用の無害化」の「制御文字と bidi 制御文字」を、Unicode の定義で読んだもの):

| 対象 | code point |
|---|---|
| 制御文字 (General_Category が Cc) | U+0000〜U+001F (タブ、改行、復帰、ESC を含む)、U+007F、U+0080〜U+009F |
| bidi の制御文字 (Bidi_Control の性質を持つ 12 個) | U+061C、U+200E、U+200F、U+202A〜U+202E、U+2066〜U+2069 |

- タブと改行もエスケープする。値の中の改行をそのまま出すと、1 つの値が複数の行や別の項目に見える
- C1 (U+0080〜U+009F) は、端末によっては 1 文字で制御列の始まり (U+009B) として働く

長さと切り詰め:

- 数える単位は char。書記素や表示の桁幅では数えない (Unicode の表か表示先の知識が要り、Context の「増やしたくないもの」に当たる)
- 切り詰める時は、出力の末尾に印 `…` (U+2026) を 1 つ付ける。印は `max_chars` に数えない (`max_chars` が何を数えるかは S4)
  - DESIGN-ja は切り詰めたことが分かる形を求める。印を上限の中に数えると、`max_chars` が印より短い時に、上限を破るか印を落とすかの場合分けが要る。外に置けば、どの `max_chars` でも同じ規則で印が付く
- `max_chars = 0` は特別に扱わない。空でない値は印だけになり、空の値は空のまま
- エスケープ 1 個は途中で切らない。入りきらないエスケープは丸ごと落とす (`\u{20` で終わる出力は、別の文字に読める)
- 書記素の途中 (基底の文字と結合文字の間、絵文字の連結の途中) では切れうる

使い方:

- 照合と保存には元の値を使い、この関数の出力は表示にだけ使う (DESIGN-ja)
- 通すのは表示の直前に 1 回。出力をもう一度通した結果が同じになることは保証しない

### 裁定待ちの分岐

4 つの分岐は互いに独立で、どれも既存の文書からは決まらない。各分岐の推奨は 1 つずつ示すが、決定ではない。

#### S1: 出力から元の文字列が 1 つに決まるか (単射か)

| 案 | 中身 | 意味と帰結 |
|---|---|---|
| a (推奨) | `\` 自体を `\\` に、元の値の中の `…` (U+2026) を `\u{2026}` にエスケープする | 切り詰めが無ければ、出力から元の文字列が 1 つに決まる。出力に現れる `\u{…}` は必ずエスケープで、素の `…` は必ず切り詰めの印。`\` を含む値 (正規表現の引数など) は `\` が 2 つに見える |
| b | `\` と `…` はそのまま出す | 対象の文字が表示を変えないことだけを保証する。値の中の文字どおりの `\u{202e}` と、エスケープされた U+202E は同じ表示になり、末尾の `…` が値の一部か印かは分からない。`\` を含む値はそのまま読める |

- 推奨の理由: 表示は利用者が承認を判断する材料で、違う 2 つの値が同じ表示になると、どちらを承認したのかが画面から決まらない。DESIGN-ja の「切り詰めたことが分かる形」も、値の末尾の `…` と区別できて初めて成り立つ
- b を採る場合に受け入れること: 制御文字を含む値と、その書き方を文字として含む値を、利用者は画面で区別できない

#### S2: 対象の文字の範囲

| 案 | 対象 | 意味と帰結 |
|---|---|---|
| a | 制御文字 (Cc) と bidi の制御文字だけ (DESIGN-ja の文言どおり) | 表示の入れ替えと端末の操作を防ぐ。見えない文字 (ゼロ幅の空白 U+200B、U+2060、U+FEFF など) と行の区切り (U+2028、U+2029) はそのまま出るので、見えない文字を挟んだ別のパスが同じ表示になり、U+2028 を改行として扱う表示先では行が送られる |
| b (推奨) | General_Category が Cc、Cf、Zl、Zp の文字 (bidi の制御文字は全部 Cf に入る) | 上に加えて、見えない書式文字と行の区切りも `\u{…}` で見える。範囲は Unicode の General_Category だけで言える。絵文字の連結 (U+200D) や、ZWNJ を使う言語の文章は、その文字がエスケープで表示される |

- 推奨の理由: 目的 (値が自分の外の表示を変えず、利用者が見たものから値が分かる) に対して、見えない文字は bidi の制御文字と同じ働きをする。b は範囲を 1 つの性質 (General_Category) で言え、文字ごとの判断を持たない
- どちらでも、表を core に持つ (依存は足さない)。a は 2 つの範囲と 12 個、b は Cf の範囲の表が加わり、Unicode の版に追従する保守が要る。表が依拠する版は実装の時に `Unicode 版 選定判断基準日: YYYY-MM-DD` として記す。その版で未割り当ての code point が後の版で Cf になった場合、表を更新するまではそのまま出る
- 空白に見える別の文字 (U+00A0、U+3000 など Zs) と変種の指定 (U+FE0F など) は、どちらの案でも対象にしない (値の区切りと見た目は表示するアプリの責務。Context の表)

#### S3: よく出る制御文字の短い書き方

| 案 | 書き方 | 意味と帰結 |
|---|---|---|
| a (推奨) | 全部 `\u{…}` (S1 の a なら `\\` だけが別) | 書き方の規則が 1 つ。改行は `\u{a}`、タブは `\u{9}` と出る |
| b | タブ・改行・復帰だけ `\t`、`\n`、`\r` と書き、他は `\u{…}` | プログラムを書く人には読みやすい。書き方が 2 系統になり、表が 3 行増える |

- 推奨の理由: 保証する性質は同じで、違いは読みやすさだけ。増やしたくないもの (文字ごとに違う書き方) に照らして a

#### S4: `max_chars` が数えるもの

| 案 | 数えるもの | 意味と帰結 |
|---|---|---|
| a (推奨) | 出力の char (エスケープした後。印は除く) | 返る文字列は最大で `max_chars` + 1 char。画面に出る量の上限を呼び出し側が決められる。元の値の何文字目まで出るかは、エスケープの数で変わる |
| b | 元の値の char (エスケープする前) | 元の値の先頭 `max_chars` 文字が必ず出る。返る文字列は最大で `max_chars` × 10 + 1 char (`\u{10ffff}` は 10 char) で、出る量を相手が 10 倍まで伸ばせる |

- 推奨の理由: 切り詰めの目的は画面に出る量を抑えることで、量を決めるのは出力の側

### 例 (各分岐で推奨を採った場合)

| 元の値 | `max_chars` | 出力 |
|---|---|---|
| `ls -la` | 80 | `ls -la` |
| `a` + U+202E + `b` | 80 | `a\u{202e}b` |
| `a` + 改行 + `b` | 80 | `a\u{a}b` |
| `a\.b` | 80 | `a\\.b` |
| `abcdef` | 3 | `abc…` |
| `ab` + U+202E + `c` | 5 | `ab…` (エスケープが 8 char で入りきらないので、丸ごと落とす) |
| `abc` | 0 | `…` |
| 空 | 0 | 空 |

## 不採用案と理由

| 案 | 不採用理由 |
|---|---|
| 対象の文字を取り除く | 値に何が入っていたかが画面から消え、違う値が同じ表示になる。DESIGN-ja は「エスケープして見せる」 |
| 対象の文字を 1 つの代わりの文字 (U+FFFD や `?`) に置き換える | どの文字だったかが分からず、違う値が同じ表示になる |
| 制御文字の図記号 (U+2400 台) で見せる | 図記号があるのは C0 と DEL だけで、C1 と bidi の制御文字には別の書き方が要る。図記号が出るかはフォントで決まる |
| キャレットの書き方 (`^[`) | 書けるのは C0 と DEL だけで、他の対象に別の書き方が要る |
| `\x1b` の書き方 | 2 桁では U+0100 以上を書けず、書き方が 2 系統になる。U+0080〜U+00FF では、バイトの値と code point のどちらかが読み手に分からない |
| 戻り値を、文字列と切り詰めの有無の組にする | 型が 1 つ増える。印を画面に出すかが呼び出し側に移り、出し忘れると切り詰めが見えない。DESIGN-ja の「切り詰めたことが分かる形」は文字列の形で満たせる |
| 対象の範囲や書き方を引数で選べるようにする | 入口の変種が増え、呼び出し箇所ごとに保証が変わる (増やしたくないもの) |
| 書記素、または表示の桁幅で数える | 書記素の区切りと文字の幅の表が要り、core の依存か表が増える。桁幅は端末とフォントで決まる表示先の知識 |
| 印に、落とした文字の数を添える (`…(+123)`) | 印の長さが値で変わり、上限の規則が増える。元の値の長さは、元の値を持つ呼び出し側が数えられる |

## Consequences

- 返る文字列には対象の文字が入らない。表示先の構文 (HTML など) のエスケープは、呼び出し側がこの出力に対して行う
- 呼び出し側は、表示の直前に 1 回だけ通す。照合、保存、ルールの値にはこの出力を使わない
- 切り詰めた出力からは、値の残りの長さは分からない。要る時は呼び出し側が元の値から数える
- 採られた時に直す所:
  - `crates/procline-core/src/sanitize.rs` の実装と doc
  - DESIGN-ja / DESIGN「表示用の無害化」に、書き方、対象の範囲、長さの数え方、印を書く (S2 で b を採るなら「制御文字と bidi 制御文字」の文言を広げる)
- テストで保つ性質 (規則を緩める変更を検出する):
  - 出力に対象の文字が 1 つも無い
  - 出力の char の数が上限を超えない (S4)
  - エスケープの途中で終わる出力が無い
  - 印が付くのは切り詰めた時だけ
  - S1 で a を採るなら、切り詰めの無い出力をテストの中の復号で戻すと元の値になる
- 対象の表は Unicode の版に依る。版を上げる時に表を見直す
- procline-cli の出力 (収集の結果の JSON) はこの関数を通らない。JSON の文字列のエスケープは JSON の構文のためのもので、この DR の対象と同じではない。端末に出す JSON に入る argv やパスの扱いは、CLI の側で決める ([issue](../issue/2026-11-15-procline-cli.md))
- 未観測: 対象の文字をそのまま出した時に、端末や画面の部品がどう表示するかは観測していない。この DR の規則は、その振る舞いに依らない (対象を全部エスケープする)
